# Chat Application

Welcome to my Chat Application! This project is a full-fledged realtime messaging application with a user interface 
inspired by WhatsApp. It enables users to exchange messages individually or within groups.

## ⚠️ Security Disclosures

Before using or evaluating this project, please understand these important security characteristics:

### End-to-End Encryption (E2EE) Limitations

This application implements **end-to-end encryption against passive network attackers** (e.g., TLS termination, ISP surveillance). However:

1. **No out-of-band identity verification** — The client uses Trust-On-First-Use (TOFU) for peer identity keys. A compromised or malicious server could swap a user's public keys transparently, and the client would silently accept them. Unlike Signal, there is no safety-number verification flow to detect this. **This is NOT meaningful E2EE against a malicious/compromised server.**

2. **Client-side key security is bounded by password strength** — The encryption key bundle stored in IndexedDB is encrypted with a key derived from your login password (PBKDF2 600,000 iterations). A weak password directly weakens message confidentiality at rest.

3. **The Double Ratchet implementation uses Curve25519 (X25519) keys generated by the Signal Protocol library** (`@privacyresearch/libsignal-protocol-typescript`). All message encryption goes through the Double Ratchet for forward secrecy; there is no legacy RSA path.

### Security Architecture Notes

- ✅ **Forward secrecy**: Message keys are deleted immediately after use (Double Ratchet)
- ✅ **Atomic key regeneration**: Rollback on partial failure prevents key loss
- ✅ **Atomic one-time pre-key consumption**: PostgreSQL `FOR UPDATE` CTE prevents replay
- ✅ **No plaintext logging**: Logger utility hashes sensitive values before logging
- ⚠️ **TOFU identity model**: Accepts any identity key on first sight — manually verify with peers

### Architecture Decisions

**Own-message cache is per-device by design.** The sender never creates a Double Ratchet self-session (the protocol cannot decrypt messages on their own sending chain - this is a known Signal Protocol limitation). Instead, the sender's own plaintext is cached locally, encrypted at rest with a device-local key that never leaves the device or touches the server. This matches Signal's own behavior prior to multi-device linking: if local storage is cleared, or the same account is opened on a second device/browser, the sender's own historical messages will be unavailable on that device until multi-device sync (a genuine per-device X3DH handshake) is implemented as a future feature. This is an intentional trade-off to preserve E2EE-at-rest - the server never stores the sender's own plaintext.

## Features

- **Realtime Messaging:** Experience seamless, real-time messaging with instant message delivery.
- **Individual Messaging:** Send private messages to other users.
- **Group Messaging:** Create and edit groups to communicate with more than one user.
- **Login And Signup:** Securely access the application with a login and signup system.
- **End-to-End Encryption:** Messages are encrypted with AES-256-GCM via the Signal Protocol Double Ratchet (forward secrecy), using Curve25519 keys.

## Technologies

- **Frontend:** Typescript with React
- **Backend:** Java with Spring Boot, Spring Security, Spring Websocket and Spring Data JPA
- **Database:** PostgreSQL
- **Authentication:** JSON Web Token (JWT) — stored in httpOnly, SameSite cookie
- **State Management:** Redux, Thunk
- **Component Library:** Material UI
- **Encryption:** Web Crypto API, Signal Protocol (`@privacyresearch/libsignal-protocol-typescript`)

## Getting Started

### Prerequisites

Ensure you have **npm** and **mvn** installed on your machine.

### Installation

1. **Clone the repository:**  
    ```bash  
    git clone https://github.com/nicolasjusten95/chat-app.git
    ```
   
2. **Navigate to the Frontend and install the required dependencies:**  
    ```bash
    cd frontend
    npm install
    ```
   
3. **Navigate to the Backend and install the required dependencies:**  
    ```bash
    cd backend
    mvn clean install
    ```
   
4. **Configure Environment Variables:**  
   Configure the Spring Boot application.properties for database and other configurations.

5. **Run the Application:**
    - Start the frontend:
      ```bash
      npm start
      ```
    - Start the backend:
      ```bash
      mvn spring-boot:run
      ```
6. **Access the Application:**
   - Open your browser and visit [http://localhost:3000](http://localhost:3000) to use the Realtime Chat Application.
   - You can log in with a sample user to access the app with predefined data:
     - email: luke.skywalker@test.com
     - password: luke
   - Or you can create your own Accounts and start chatting!
